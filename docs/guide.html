The chip that teaches itself

A neuromorphic accelerator that learns handwriting while it runs — no training computer, no backpropagation. Here is what it does, what it scored, and how to run every experiment yourself.

01

What this actually is

Normal AI is trained on a big computer first. Only the finished result is loaded onto a chip — the chip never learns anything, it just answers.

This one works the other way round. It switches on knowing nothing, watches handwriting go past, and rewires its own connections as it looks. Nobody ever tells it "that was a seven." It works out on its own that certain shapes belong together. Only at the very end do we check which digit each part of it settled on.

The four plates above are the proof, read straight out of the chip's memory after a run. Three neurons taught themselves a zero, a one and a seven. The fourth never won a competition, so it stayed the noise it started as.

The chip doesn't physically exist yet. It's a complete blueprint, run through a simulator — a program that pretends to be the chip, wire by wire. That's why a run takes hours: one computer is imitating something silicon would do instantly.

02

Set up, once

Two things. Install the simulator:

sudo pacman -S iverilog   # Arch. On Ubuntu: sudo apt install iverilog

Then get the handwriting images and move into the working folder:

cd code/ip/03.learning-rule/stdp_engine
make download_mnist

That fetches MNIST — 70,000 photos of handwritten digits, the standard practice set. About 55 MB, once. If you already have it, it says [skip] and exits.

Check it worked. make test_all runs seven self-checks on the individual pieces — small module tests rather than a full simulation, so they finish quickly. If they pass, you're ready. Every command from here runs in that same folder.
03

The four experiments

Each is one command. Nothing to edit, no files to open. Think of a cluster as a room with a fixed number of chairs — every pixel of the picture and every learning neuron needs its own chair.

One cluster

make mnist

One room of 128 chairs. 100 hold the picture, 28 are neurons that learn. The baseline.

29.58 %

Wide best

make mnist_wide

Four rooms, each seeing the whole picture and forming its own opinion. All 112 neurons vote at the end.

41.67 %

Layered

make mnist_layered

Two stages: four rooms each study one quarter, then hand a summary to a fifth room. Barely beat guessing.

11.25 %

Wide at 14×14

make mnist_wide \
  MNIST_GRID=14 \
  MNIST_CLUSTERS=2 \
  MNIST_NEURONS=256 \
  MNIST_TIMESTEPS=15

The winning idea at higher resolution. Took 6 h 11 m — the one run we timed precisely.

32.92 %
04

Reading the result

ACCURACY : 41.67 %      100 of 240 test images
Health   : queue overflow=0  stdp timeout=0  router overflow=0

The accuracy is how many of 240 unseen pictures it got right. Guessing scores about 10%.

The health line matters more. Every number must be zero. Zeros mean the hardware ran cleanly and the score is real. Anything else means the design jammed and the score is meaningless — a fault, not a bad result. Every run so far has been all zeros.

You'll also see small pictures made of # and + characters — the plates at the top of this page are exactly that, drawn in colour. Each is what one neuron decided to look for. When learning works, you can see digit shapes in them. It's the most direct evidence that anything was learned at all.

Every run saves itself under runs/ in a date-stamped folder with the full log, the settings used, and the headline score. Nothing is ever overwritten, so old results stay comparable.

05

Designing your own

The one rule

Pixels and neurons share the same room. A 128-chair room showing a 10×10 picture spends 100 chairs on pixels, leaving 28 for neurons. Want more neurons? Only two options: a bigger room, or more rooms. More rooms is what won.

Room sizes must be 64, 128, 256, 512 or 1024 — the memory is physically wired that way. Ask for something impossible and the tool refuses in plain words rather than building something broken: 

196 inputs leaves no room for neurons in a 128-slot cluster;
raise --neurons-per-cluster to 256

What fits

PicturePixelsRoomNeurons leftSpeed
7×7496415very fast
10×1010012828a few hours
14×1419625660~4× slower
28×287841024240fits, but weeks

Full-size MNIST does fit the design — 784 + 240 = 1024. Only the simulator's speed stops us. On real silicon it would be fine.

The dials

Add any of these to the end of a command. Anything you leave out keeps its default.

DialDefaultWhat it changes
MNIST_IMAGES1200how many pictures — 60% learn / 20% label / 20% test
MNIST_GRID10picture size — 7, 10 or 14
MNIST_NEURONS128chairs per room — must be a power of two
MNIST_CLUSTERS4how many rooms
MNIST_TIMESTEPS20how long each picture is shown
MNIST_THRESHOLD1500how easily a neuron reacts — lower fires more
MNIST_MAX_RATE0.55how loudly a bright pixel shouts
MNIST_SEED1the randomness — change it to repeat a run differently

Recipes

# A quick taste — small pictures, few images, minutes not hours
make mnist_wide MNIST_GRID=7 MNIST_NEURONS=64 MNIST_IMAGES=200

# Twice the brain: 8 rooms instead of 4
make mnist_wide MNIST_CLUSTERS=8

# A 256-chair room leaves 156 chairs for neurons
make mnist_wide MNIST_NEURONS=256

# Is the best result luck? Re-run with different randomness
make mnist_wide MNIST_SEED=7

# Nothing firing? Make the neurons more sensitive
make mnist_wide MNIST_THRESHOLD=900

To check that many rooms can talk to each other without any learning — a hardware test that finishes in seconds: 

make multi_cluster                    # 4 rooms
make multi_cluster MC_CLUSTERS=32     # 32 rooms = 1024 neurons
06

What we learned

Accuracy by network shape
1200 MNIST images — 720 to learn from, 240 to label with, 240 to be tested on. Identical learning settings throughout.
Every run passed its health check with all counters at zero, so each score reflects learning, not a stalled pipeline.

Wider beats deeper, clearly

Going from 28 neurons to 112 added 12 points. More neurons looking at the same picture and voting is what helped — not more stages.

Why the layered one failed

Not a bug. The hardware ran perfectly and the first stage genuinely learned clean fragments of pen strokes. The problem is that neurons inside a room compete, and only one may win at a time. So each of the four first-stage rooms passes on a single answer. The whole picture is squeezed to about 12 bits before the second stage sees it, and nothing downstream can rebuild what was thrown away.

The lesson: competition is useful inside a layer and destructive between layers.

Why higher resolution scored worse

Not because 14×14 is a bad idea — it was simply undertrained, and the logs say so plainly. Neurons fired 14,543 times during learning versus 38,084 in the winning run: about 121 learning events each instead of 340. Only 51 of 120 neurons ever woke up, and their learned pictures came back nearly blank. It was handed 2.4× more pixels to make sense of and a third of the practice. Worth retrying with more images and the timesteps back at 20.

One stubborn problem

Digits 4 and 5 score 0% in every wide run. In the best run, digit 5 was never assigned a single neuron — impossible to predict, structurally. Digit 4 had 13 neurons assigned and still got none right; its neurons never won when it counted. Curiously, digit coverage improved steadily across the runs — 7 of 10 digits, then 9, then all 10 — even as accuracy peaked in the middle. Fixing 4 and 5 is the most promising next step.

07

How good is this, honestly?

What genuinely works

  • It learns unsupervised. During learning it is never told what any picture is. It groups similar shapes by itself; labels are attached afterwards purely to score it.
  • The learning happens in the hardware. No PC, no backpropagation. Connection strengths are updated by the circuit as spikes arrive. This is the hard part, and it works.
  • It learned from 720 examples. Conventional systems use tens of thousands.
  • It's real, synthesisable hardware — not a Python model of hardware. It could go onto an FPGA.
  • It scales. The multi-room wiring is tested to 1024 neurons, and full-resolution MNIST fits the design.

What it can't do yet

  • 42% is a long way from solved. Published work using this same family of learning rule reaches far higher, with more neurons and far more training. This is a working foundation, not a competitive recogniser.
  • Two of the ten digits don't work at all.
  • Simulation is painfully slow. Hours per experiment is the single biggest brake on progress. Real hardware removes it entirely.
  • The two-stage design is a dead end as built. It needs a different way of passing information between layers before depth will help.

The fair summary: the hard, novel thing — a chip that rewires itself while running, with no outside help — is built and demonstrably works. Turning it into an accurate recogniser is the next phase, and the obvious moves are more neurons, more training, and getting off the simulator.
